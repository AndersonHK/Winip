# Checkpoint 07 — kernel lifecycle, images, settings and MSI maintenance

Release **0.2.0**, 2026-09-13. The interrupted feature slice and queued installer request are delivered together. Development executable: `x64/Release/Winip-dev-16.exe`; installer: `Artifacts/packaging/Winip-0.2.0-x64.msi`. Generated binaries are local artifacts, not tracked source. Build identities and accepted metrics (local archive: `Artifacts/archive/validation/checkpoint07-summary.json`; not distributed) identify the actual tested sources/artifacts.

## Implemented behavior

- Kernel status has a gray disconnected, green idle or red busy circle. Run all shows a refresh symbol while busy.
- Kernel → Select interpreter selects an existing executable for this session. Interrupt (`Ctrl+Shift+I`) signals the existing kernel; Restart (`Ctrl+Shift+R`) starts an empty session without running cells. Force stop remains separate. Opening a notebook disconnects the prior session; the next execution begins at 1 independently of saved counts. Repeated Run all within an existing session continues that session's counter.
- File → Settings persists HDR On/Off, last-opened/fixed folder mode, and a fixed-folder picker. HDR is OFF by default. Both folder values initially resolve the user's Downloads known folder. Opening a valid notebook remembers its directory. The native Open dialog uses the configured folder, with Downloads fallback when the stored path no longer resolves.
- Settings are `%APPDATA%\Winip\settings.json`, written asynchronously through an atomic replacement. Unknown JSON fields survive. Invalid settings leave the original file intact, use defaults and report an error; an explicit setting change preserves the invalid original as `.invalid` before replacing it. `--sdr` / `--hdr` are session overrides. Multiple instances currently use last-writer-wins snapshots.
- Saved and live PNG/JPEG outputs render as ordered text/image blocks. Original MIME JSON is preserved. Pillow RGBA, IPython JPEG and Matplotlib inline PNG execute through the real selected Python. Unsupported images get a visible diagnostic while retaining the output data.
- MSI release numbering follows [0.major.minor](Releases.md). Reopening the same release offers Repair/Remove. A newer release offers Update using the previous folder and migrated association feature state. The previous product is retired after the new payload is installed, inside the rollback transaction. The user need not uninstall first.

## Ownership and rendering

New primary classes have matching header/source pairs: `AppSettings`, `NotebookImage`, `CellOutput`, and `ImageCache`. Decode and output text measurement occur on existing document/kernel workers; immutable prepared blocks cross to the UI/render snapshot. WIC decodes all original source pixels. Direct2D retains bounded GPU bitmaps and performs resampling, alpha composition and ICC/scRGB conversion. Source pixels remain available in CPU memory for device recovery, while reusable drawing derivatives stay on the GPU.

The color-managed path uses premultiplied alpha and FP16 effects, converts source ICC/sRGB to destination sRGB/scRGB and applies Windows SDR-white scaling for HDR. An explicit DPI-compensation effect prevents a 96-DPI source bitmap inside the effect graph from clipping at higher output DPI. A missing color-management capability or failed image preparation gives a cell-local diagnostic; device-loss errors remain renderer errors. Cached failures are cleared with the resource domain.

Current limits are explicit: PNG/JPEG only, at most 4096 pixels per source dimension, 24 MiB encoded image, 128 MiB decoded per cell and 256 MiB per loaded notebook, 16384 DIPs per display dimension. The GPU source cache is bounded to 64 MiB/128 entries; effect intermediates are driver-managed and not included in that source-bitmap accounting. PNG above 8 bits/channel is retained but not rendered yet. Untagged images assume sRGB. Wide-gamut profiles, JPEG orientation, additional formats and full HDR-content fidelity need further acceptance; the host tests use untagged/sRGB-tagged sources.

The bridge still limits a completed cell to 1 MiB/4096 output messages, the pipe response to 8 MiB, and UI publication to eight bundles. Outputs appear atomically after matching execution reply and idle. There is no post-idle interactive display update or dashboard support. Large-table/image transport expansion is planned explicitly in [Next-Slices.md](Next-Slices.md).

## Failed samples and limits

The GPU suite caught and fixed the effect-graph DPI clipping error. An early analytic sample landed on the fixture's one-pixel diagonal during downscaling and was moved to the intended solid-color region; tolerance was not relaxed. A probe initially captured HDR under an SDR filename because snapshot publication and toggling were in one phase; phases now wait for the correct presented revision.

The local ipykernel Windows interrupt path invokes `interrupt_main`. It interrupts a Python bytecode loop and preserves the surviving namespace, but a test blocked inside `time.sleep(60)` deferred interruption. Native extension behavior can likewise vary. The implementation does not pretend to provide unconditional immediate interruption; force stop/restart remain available.

Image sample `image-20260913-184751-634411` unexpectedly had two cells instead of its one-cell fixture and failed the count assertion. Sample `image-20260913-184830-422182` passed feature checks but recorded one extra frame/31.25 ms CPU during its first idle interval. These retained samples are not accepted idle evidence; their external-input/timing cause was not established. The later independent timing and visual runs pass unchanged idle gates. No claim of zero GPU time, sustained 160 Hz, complete device-loss recovery, every ICC profile, Windows 7–11 or installer lifecycle certification follows from these bounded tests.
